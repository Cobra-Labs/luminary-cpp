What Luminary does

Designed to replace older, less maintainable approaches with a cleaner C++ engine.

⚙️

Core engine

The engine layer manages the run loop, universe state, patch logic, and behavior of lighting scenes. It is built to stay deterministic and efficient under real-time control.

🌐

Network protocols

Support for UDP, Art-Net, and associated protocol handling enables communication with modern lighting systems and control infrastructure.

💡

Fixture intelligence

Fixture definitions are treated as runtime assets. These are integrated with open fixture language tooling to keep show data and device descriptions aligned.

🔒

Security & auth

Pin-based auth and secure endpoint patterns help keep remote access controlled, especially in networked installations and bridge scenarios.

🧩

Remote bridge

Remote connectivity gives Luminary a bridge layer for external orchestration, service discovery, and headless integration points.

📡

Node discovery

Built-in discovery utilities help identify peers and devices within the network, improving automation and operational visibility.

Architecture

Structured around a clean separation between engine logic, protocol I/O, and runtime assets.

  • ✓ Core runtime
    Universe state, engine lifecycle, patching logic, DMX types
  • ✓ Protocol layer
    Art-Net, UDP, polling, socket handling, state transfer
  • ✓ Network services
    HTTP server, discovery, remote bridge, auth gatekeeping
  • ✓ Fixtures
    Runtime fixture definitions shipped next to executable output

Build it locally

Minimal setup using CMake and the included project files.

git clone https://github.com/Cobra-Labs/luminary-cpp.git
cd luminary-cpp

cmake -S . -B build
cmake --build build

./build/luminary
